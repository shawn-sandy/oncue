# Plan: Show ElevenLabs credits in every OnCue session, estimated for everyone and exact with a key

## Objective

Add a mod (a Claude Code hooks module) to the existing `oncue` plugin that, with no setup, estimates the credits each `creative_generate_speech` call spends (characters x model rate x takes) and shows the session total, and that, once the user sets an ElevenLabs API key, replaces the estimate with the exact balance from `GET /v1/user/subscription`: used and remaining credits and takes left in the status line, pace against the reset date, past-due and overage warnings, a 10-minute refresh, a toast after each connector call, and an `/elevenlabs` command that also lists voice slots.

## Context

OnCue's voiceover skill (`plugins/oncue/skills/voiceover/SKILL.md`) generates speech and transcripts through the ElevenLabs connector, and the explainer-video skill tells Claude to report "what it cost in ElevenLabs credits". Today Claude can only estimate that from reference figures (about 1,100 credits a take for a 75-second read, quoted in the voiceover and setup skills and the README). The README tells Claude Code users to add the connector as `claude mcp add --transport http elevenlabs https://api.elevenlabs.io/v1/mcp`, so its tools arrive as `mcp__elevenlabs__creative_*`; a connector added in the Claude app gets a generated server name instead, which is why the mod matches `/^mcp__.+__creative_/`.

No ElevenLabs connector reports the account's balance. The hosted ElevenLabs MCP server (`https://api.elevenlabs.io/v1/mcp`, the "full" connector) lists agents, conversations, tests, knowledge base, a per-agent LLM cost estimate and text-to-speech, but no subscription, credits or usage tool, and its OAuth scopes cover only ElevenAgents and Text to Speech. The restricted connector OnCue uses is the same server without image, video and music. A mod cannot reuse the connector's sign-in either: the only credential a mod can borrow (`$.session.authorize()`) is the session's Anthropic one, for first-party hosts. So the exact balance needs the user's own API key, and a keyless user can get only an estimate.

The keyless estimate comes from the call itself. A `tool.call` hook sees the `creative_generate_speech` input: `prompt` (the text), `model_id` (one of `eleven_v4`, `eleven_v3`, `eleven_multilingual_v2`, `eleven_flash_v2_5`, `eleven_turbo_v2_5`), `generations_count` (takes, 1 to 4, default 2) and `estimate_only` (prices a run without generating). ElevenLabs does not publish per-character credit rates. Its API pricing page bills v4, v3 and Multilingual v2 at $0.08 per 1,000 characters and Flash and Turbo at $0.04, half as much. The Gleaner example's voiceover script is 1,121 characters and reads in about 73 seconds, which fits the skills' figure of about 1,100 credits a take for a 75-second read. This plan therefore assumes 1 credit per character for v4, v3 and Multilingual v2, and 0.5 for Flash and Turbo, and step 14 checks the assumption against the usage page.

The exact path uses `GET https://api.elevenlabs.io/v1/user/subscription` with an `xi-api-key` header. The fields this plan reads: `character_count` (credits used this period), `character_limit` (credits allowed), `next_character_count_reset_unix` (may be null), `character_refresh_period` (`monthly_period`, `3_month_period`, `6_month_period`, `annual_period`, or null), `tier`, `status` (`trialing`, `active`, `incomplete`, `past_due`, `free`, `free_disabled`), `current_overage` (`{ amount, currency }`, the usage-based overage cost so far), `voice_slots_used`, `voice_limit`, `professional_voice_slots_used` and `professional_voice_limit`. ElevenLabs bills in credits but still names the fields `character_*`.

The mod API facts (from the Claude Code mod types, build 2.1.30x): `$.http.fetch` reaches the network through the host; `userConfig` fields marked `"sensitive": true` live in the platform's secure credential store, not `settings.json`, and `claude plugin configure <plugin>` shows a plugin's options and saves values with `--values-stdin`; `$.ui.status`, `$.ui.toast`, `$.clock.every`, `$.clock.after` and `$.command.register` exist; a `tool.call` matcher accepts a RegExp, and a hook sees the call's input and, after `await next(e)`, its result; `claude plugin test` runs `*.test.ts` files against the engine with `mock.clock(on, { now })` and hookable `http.fetch`, `ui.status` and `ui.toast`, but refuses to run at all until `hooks/hooks.json` names a module.

Risks and mitigations:

- The rate table is an assumption and can go stale when ElevenLabs reprices or adds a model. Mitigation: every figure is labelled an estimate, an unknown `model_id` counts at 1 credit per character, a `ponytail:` comment names the ceiling, and step 14 measures the gap.
- The estimate misses spend it cannot see: transcription (the mod never learns the audio's length), takes started from the speech view's voice switcher (they do not pass through a Claude Code tool call), and anything spent outside this session. Mitigation: the README and `/elevenlabs` say so, and point to the API key for exact numbers.
- Takes left and pace are projections: takes left assumes future takes cost what this session's did (or the 1,100-credit reference before the first one), and pace assumes spending continues at the period's average rate over approximate period lengths. Mitigation: both are prefixed "≈" or "~", and pace is skipped when there is too little data.
- The connector generates asynchronously, so the exact balance changes some time after the call. Mitigation: with a key, follow-up refreshes run at 20 s, 60 s and 180 s after each connector call, and the toast reports any observed drop.
- The API key may belong to a different ElevenLabs workspace than the connector's sign-in, in which case the balance is right but the toast never fires. Mitigation: the README tells the user to create the key in the same workspace the connector uses.
- Sandboxed sessions (claude.ai, Cowork) may block `api.elevenlabs.io`. Mitigation: a failed fetch shows a one-line status and never throws; the keyless estimate needs no network at all.
- The `creative_*` tool-name pattern matches the hosted ElevenLabs connector's naming only. Mitigation: a `ponytail:` comment names the ceiling; keyed users still get the 10-minute refresh.
- A past-due account or paid overage is hard to produce on a real account, so step 14 cannot exercise those warnings live. Mitigation: step 5 pins both with mocked payloads.
- Whether `claude plugin configure oncue --values-stdin` stores a sensitive option in secure storage, and what the enable-time prompt looks like for a plugin update that adds one, is unverified. Mitigation: step 14 confirms it live and updates the README with what worked.
- A key restricted by scope needs read access to user info; the exact permission name is not in the docs, and a key without it most likely gets a 403. Mitigation: a 403 shows its own message, and step 14 tests with a restricted key and records the permission in the README.

## Decisions

- Hybrid: every user gets the keyless estimate, and setting `elevenlabs_api_key` upgrades to the exact balance (chosen by the user), because no ElevenLabs connector exposes the balance and a mod cannot borrow the connector's sign-in.
- The estimate is characters x model rate x takes (the user's formula), with rates of 1 credit per character for `eleven_v4`, `eleven_v3` and `eleven_multilingual_v2`, 0.5 for `eleven_flash_v2_5` and `eleven_turbo_v2_5`, and 1 for any other model, because ElevenLabs publishes only relative prices (Flash and Turbo at half) and the Gleaner script fits 1 per character.
- Characters are counted by code point (`[...prompt].length`), not UTF-16 length, so an emoji counts once.
- Only `creative_generate_speech` calls that ran are counted: a call with `estimate_only: true`, a denied call and a call whose result is an error add nothing, because none of them spends credits. The estimate is computed in both modes (takes left needs it) but shown only without a key.
- With a key set, the exact balance replaces the estimate everywhere (status, toast, `/elevenlabs`), so the user never sees two competing numbers.
- Without a key the mod stays silent until the first speech call: no status line, no requests, and `/elevenlabs` shows the session estimate and how to add a key with `claude plugin configure oncue`, because most OnCue users should not be nagged before they spend anything.
- Takes left (keyed only, chosen by the user) is remaining credits divided by the average estimated credits per take this session, or by 1,100 (the skills' reference for a 75-second read) before the session's first take, rounded down, shown as `(≈N takes)` after the remaining figure and omitted at 0 left, because exact per-take cost cannot be attributed from balance changes.
- Pace (keyed only, chosen by the user) is credits used divided by days elapsed in the refresh period, where elapsed is the period length (30, 91, 182 or 365 days for `character_refresh_period`) minus the days to reset. When remaining divided by that rate falls short of the days to reset, the shortfall in days is rounded to the nearest whole day (at least 1) and the status line adds `· out ~Nd early`; `/elevenlabs` always states the pace. It is skipped when `character_refresh_period` or the reset is null, or less than one day of the period has passed, because the projection is noise then.
- Past due and paid overage (chosen by the user) each add a status suffix while true and raise one toast per session: `status: "past_due"` adds `· payment past due`, and `current_overage.amount` above zero turns the remaining figure into `0 left · overage <amount> <CURRENCY>`. Other statuses (`incomplete`, `free_disabled`) are not flagged because the user asked for these two.
- The overage amount is shown as ElevenLabs' amount string plus the upper-cased currency code (`3.20 USD`), not a currency symbol, because that needs no symbol table and covers every currency the API returns.
- Voice slots appear only in `/elevenlabs` (`Voices: 7 of 10 slots (professional 1 of 1)`), because they matter only to people designing and saving voices and would crowd the status line.
- HTTP failures map to three messages: 401 and 403 show `ElevenLabs: key rejected (<status>)`, any other non-2xx shows `ElevenLabs: error <status>`, and a fetch that rejects shows `ElevenLabs: unreachable`, because the user can act on a rejected key but not on a server error.
- The mod lives inside `plugins/oncue/`, not as a second marketplace plugin, because that is where the user asked for it, it needs no `marketplace.json` entry, and `scripts/validate.mjs` (which crashes on a plugin with no `skills/` folder) needs no change.
- `elevenlabs_api_key` is optional, because a required `userConfig` field with no value fails the whole plugin's load.
- The plugin goes to 1.2.0 (main is at 1.1.0). The repo's CLAUDE.md asks for a bump when what a skill or the engine does changes; the mod is neither, but it changes what the plugin does in every session, so it gets a minor bump.
- One endpoint, `GET /v1/user/subscription`, because it returns every field above in one call; `/v1/usage/character-stats` is deprecated and only needed for history.
- With a key, the spend toast fires on any balance drop a refresh sees, including spend from the ElevenLabs website or other apps (confirmed with the user), because "credits spent since the last check" needs no call-tracking state.
- Status line first, because it is the smallest code; step 14 checks the desktop app draws it, and an `AbovePrompt` band (`ui.render` hook) is the fallback.
- "resets in N days" instead of a calendar date, because it has no timezone dependence and is deterministic under `mock.clock`.
- Thousands separators come from a regex, not `toLocaleString`, because the mod runtime has no Node or DOM and `Intl` availability there is unverified.
- No `$.state` contract: the session estimate, the last balance and the once-per-session warning flags are module variables, so a module reload (which setting the key triggers) starts them over; nothing drawn reads shared state.
- The API host is hard-coded to `https://api.elevenlabs.io` (confirmed with the user: no data-residency account).

## Acceptance Criteria

- [ ] Without a key, each `creative_generate_speech` call that runs produces a toast and a status-line total labelled as an estimate, and no request goes to ElevenLabs.
- [ ] For a two-take `eleven_v4` speech generation with no transcription, the estimate is within 10% of the text-to-speech credits the ElevenLabs usage page shows for it.
- [ ] With a valid key, the status line shows remaining credits, used credits and days to reset, matching the ElevenLabs dashboard, and no estimate appears.
- [ ] With a key, the status line shows takes left as remaining credits divided by the session's average take, or by 1,100 before the first take, rounded down.
