OnCue's setup skill now covers the plugin as well as what it needs on the machine. Ask Claude to set up, update or share OnCue, and it first reports which version is loaded and how it was installed, then gives the commands for the change you asked for.

An update now also reaches project folders that already hold a copy of the engine. Before this change those folders kept running the old engine without saying so. The work ships as OnCue 1.2.0 in pull request 7, open against main with its validate check passing.

What changed

Three changes

Setup starts with the plugin itself

Affects
OnCue users, and teammates installing it in a shared repository.
What is new

/oncue:setup has a new first step. It reads the loaded version from plugins/oncue/.claude-plugin/plugin.json, runs claude plugin list --json to find the install scope that applies to the current folder, and flags an update that is on disk but not loaded yet.

It then gives the commands to update OnCue or install it for collaborators. It runs them only when the person asks for that change. When they only asked to update or share, it stops after this step instead of running every dependency check.

How to reach it
Ask Claude to "set up OnCue", "update OnCue" or "share OnCue with my team", or run /oncue:setup.

Old engine copies are replaced after an update

Affects
Anyone who updates OnCue after making a Short in a folder.
What is new

The setup and explainer-video skills used to reuse any oncue-engine/ folder they found. Now they first compare it with the loaded plugin's compiled engine using diff -rq <plugin>/engine/dist oncue-engine/dist.

No output means the copy matches, and it is reused. Any difference means an older OnCue made it: the copy is renamed to oncue-engine.old, a fresh one is made, and Playwright and any fonts the old copy had are reinstalled. The storyboard, vertical-deck and animate-short skills set up the engine through explainer-video, so they get the same check.

How to reach it
Automatic, the next time any OnCue stage runs in that folder.

Decisions

Six calls, with what was turned down

  1. Extend the setup skill instead of adding an install skill

    A separate install skill would trigger on the same requests ("set up", "install", "update"). And no skill inside a plugin can run before the plugin is installed, so its only real jobs were updating, scope and sharing, which fit as one step of setup.

    Turned down: a new install skill, which would have duplicated setup's triggers.

  2. Spot an old engine copy by comparing engine/dist

    The compiled engine is the part an update changes, and nobody edits it by hand.

    Turned down: comparing the engine's package.json version, which stayed at 1.0.0 when 1.1.0 changed dist/capture.js; and comparing package.json contents, which always differ because Playwright and fonts are saved into the copy.

  3. Rename the old copy aside

    Renaming loses nothing, and the person deletes the old copy once the new one works.

    Turned down: copying over it, because cp -R onto an existing folder nests the engine inside it and overwriting package.json drops the saved Playwright and fonts; and deleting it, which cannot be undone.

  4. Give the commands, and run them only on request

    Plugin scope and updates live in the person's own Claude Code settings.

    Turned down: running claude plugin update or a project-scope install automatically.

  5. Keep "Claude Code 2.1.292 or later" in the collaborator command

    The review flagged it as unsourced, but the Claude Code docs state that minimum for installing with --marketplace from a shell.

    Turned down: removing the version note.

  6. Release as 1.2.0

    The repository's CLAUDE.md asks for a version bump whenever what a skill does changes.

    Turned down: a patch release, since this adds behavior. Two plans on main also name 1.2.0 (see Open items).

Review

A fresh-context review of the branch found no critical defects. Its confirmed findings were fixed in commit a1d846d:

  • choose the oncue@oncue entries that apply to this folder
  • stop after step 1 for update-only and share-only requests
  • drop --scope from the update command, which auto-detects it
  • define <plugin> in the explainer-video skill

One claim the review didn't flag was also corrected. OnCue's marketplace entry is a relative path, which the docs say can load without an install record, so "a project-scope install never downloads OnCue for collaborators" was too broad.

Learnings

Gotchas found along the way

  • claude plugin list --json returns one entry per scope and project, so a plugin installed in several repositories appears many times under the same id. Picking the right entry needs the current folder.

  • claude plugin update works out the scope on its own, and its output says a restart is needed. /reload-plugins or a new session loads the update.

  • Plugins from marketplaces outside Anthropic's official ones do not auto-update unless the person turns it on under /plugin, Marketplaces.

  • A plugin update changes only the plugin cache. A copy of the plugin's files in a working folder stays as it was, which is how the 1.1.0 engine change never reached folders set up under 1.0.0.

Open items

Still to settle

  • Version collision

    This PR takes 1.2.0. docs/plans/add-research-and-visuals-skills.md and docs/plans/add-elevenlabs-credits-status.md on main also plan a 1.2.0. Whichever lands after this PR should bump to the next minor version and update its plan.

  • CodeRabbit did not review

    Its comment on the PR reports a review rate limit, so the fresh-context review above is the only review so far. The validate check passes.

  • Not yet run in a live session

    The new step 1 and the engine copy check were verified by npm run validate, against claude plugin --help and the Claude Code docs, and by running the diff -rq check on a fresh copy and a 1.0.0 copy in a scratch folder. Nobody has yet run /oncue:setup after a real plugin update.

  • Old copies left behind

    Each update that replaces an engine copy leaves an oncue-engine.old folder, node_modules included, until the person deletes it. Setup tells them, but nothing deletes it for them.

Glossary

Terms on this page

OnCue
A Claude Code plugin that turns a topic into a vertical explainer video, a 9:16 slide deck and a voiceover.
Plugin
A package of skills and other extensions that Claude Code installs from a marketplace.
Marketplace
A catalog of plugins. OnCue's is the GitHub repository shawn-sandy/oncue, registered under the name oncue.
Skill
A set of instructions Claude follows for one kind of task, such as setup or explainer-video.
Install scope
Who gets a plugin: user scope is you in every project, project scope is everyone in a repository (recorded in its committed .claude/settings.json), and local scope is you in one repository only.
Engine
OnCue's Node program that renders the deck, stills and video from short.json.
oncue-engine/
The copy of the engine that OnCue's skills make in the working folder, so installing packages never touches the plugin's own files.
dist/
The engine's compiled JavaScript, shipped with the plugin; the part an OnCue update changes.
Playwright
The library that drives a headless Chromium browser to draw the video frames.
@fontsource packages
npm packages that supply the fonts a brand asks for.
/reload-plugins
The Claude Code command that loads plugin changes into the running session.
diff -rq
A shell command that compares two folders and lists only the files that differ.
